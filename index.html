    Firebase接続（全員のスマホと共有）

    Firebaseの Cloud Firestore に接続すると、約150人それぞれのスマホからの投稿が1つのスクリーンにリアルタイムで集まります。同時接続数の上限がないため150人規模でも使え、無料枠（Sparkプラン）で足ります。

    1. Firebaseコンソールでプロジェクトを作成する（名前は自由、GoogleアナリティクスはオフでOK）
    2. 左メニュー「構築 → Firestore Database」でデータベースを作成する。場所は asia-northeast1（東京）、本番環境モードで開始する
    3. Firestoreの「ルール」タブに、下記のルールを貼り付けて公開する（本番環境モードの初期ルールは全拒否のため、この変更が必須です）
    4. プロジェクトの概要画面で Webアプリ（</>）を登録すると表示される firebaseConfig をコピーする
    5. 下の欄に貼り付けて「Firebaseに接続」を押す（この画面での動作確認用）
    6. 本番（GitHub Pages）では必須：下の「設定入りHTMLをダウンロード」で、設定を埋め込んだ完成品HTMLを保存し、それをGitHub Pagesへアップロードする。全員のスマホはその設定で開いた瞬間に自動接続します

    Firestoreの「ルール」タブに下記を貼り付けてください。コメントと表示設定だけを公開で読み書きできるようにするルールです。イベント専用プロジェクトとして使い、終了後はプロジェクトごと削除する前提です。開催日が決まっている場合は、2行目の期限（2027年1月31日）を当日の翌日などに変えると、その日時を過ぎたら自動で書き込みが止まります。

    rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { function inEventPeriod() { return request.time < timestamp.date(2027, 1, 31); } match /comments/{commentId} { allow read: if true; allow create, update, delete: if inEventPeriod(); } match /settings/{docId} { allow read: if true; allow write: if inEventPeriod(); } } }

    当日の使い方（パス分けと権限）

    1. 事前準備：上の「Firebase接続」の手順で設定を済ませ、「設定入りHTMLをダウンロード」で作った完成品をGitHub Pagesに公開する
    2. 参加者には投稿専用のURLをQRコードなどで配布する。参加者はコメント投稿のみ可能で、再生・速度・文字サイズなどの設定は一切表示されません。投稿はFirebase経由で全端末に即時反映されます
    3. 管理者用パス（実行委員だけに別途共有したランダム16桁のパス）は参加者には配布しない。このパスで開くと設定変更と全コメントの管理が使えます（設定変更もFirebase経由で投影画面に同期します）。ページのソースにはパスのハッシュ値だけを保持し、パスそのものは埋め込んでいません
    4. 参加者は自分が投稿したコメントだけ、右側の「編集」「削除」から直せます。他の人の投稿は見るだけです（同じスマホ・同じ表示のあいだだけ「自分の投稿」と判定します）
